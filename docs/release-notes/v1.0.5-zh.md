# 测智雷达 v1.0.5

作者：ahui。此文件对应 GitHub `v1.0.5` Tag 与 Release 的正式发布内容。

本版将 Responses 与 Chat Completions 统一为主动流式请求，增加有界传输诊断，并修复切换协议后卡片隐藏上次回答的问题。支持 Windows 10/11 x64，采用 GPL-3.0-only。

## 改进与修复

### 双协议流式请求

- 两种协议均发送 `stream: true`，改善长推理时等待首字节的兼容性；手动、自动测试及“测试连接”共用请求方式。界面仍在完整响应后展示结果，无需新增设置；保留现有协议及回退开关，不另发非流式请求。
- Responses 继续从唯一 `response.completed` 的完整响应提取最终助手正文。Chat Completions 新增独立 SSE 解析，只拼接同一响应、单一候选的 `delta.content`，保留空格和换行，排除推理及用量；须正常 `stop`、完整 `[DONE]` 和 HTTP EOF 才可成功。
- 兼容 BOM、常见换行、保活注释、多行 data 及标准用量尾块；拒绝混合响应、多个候选、损坏事件、拒绝回答和工具调用。网关忽略流式而返回完整 JSON 时继续使用原解析。读取中断、超限、取消、超时及不完整结束仍报错，不凭部分正文判成功。
- 原 2 MiB 整段正文上限、取消优先和共享总期限保持。关闭协议回退只尝试所选协议一次；显式开启后，请求错误至多尝试另一协议一次，可能产生额外费用，不重新获得一份总超时。

### 本地传输诊断

- 正式手动/自动测试的每次协议尝试均尽力保存纯元数据，包括成功对照、收到响应头之前的连接失败及正文中断。“测试连接”和模型拉取不采集，诊断不增加 API 调用。
- 文件位于 `%APPDATA%\com.ahui.model-probe\response-diagnostics\transport`，按 UTC 时间和 UUID 命名；记录实际协议/流式值、等待响应头及首个正文块的耗时、HTTP 信息、字节数、完整性和脱敏底层错误链。回退以本地 `trace_id` 关联，缺失的状态码和请求编号明确为空，不猜测服务器内部原因。
- 独立最多保留 20 份、每份 64 KiB，与原 Responses 正文诊断共用最多四个后台任务。不记录请求体、回答、接口地址、鉴权头或凭据，不自动上传；队列满、磁盘故障或程序退出可能缺文件，但不覆盖测试结果、不阻止历史结算、不重试请求。原 Responses 异常正文的格式、目录和留存边界保持。

### 卡片历史与交互

- 同分组切换协议等条件后，优先恢复完整条件匹配的最近保留记录；无匹配时继续展示该分组上次回答、HTML、时间和耗时，支持原文复制和统一预览，标注“上次回答 · 当次协议”及“待重新测试”。
- 旧回答可查看，当前有效结论仍须精确匹配；不跨分组取记录、不跳过最近失败/取消。错误或取消记录的部分 HTML 不运行，清空历史后无记录可恢复；查看不请求模型、不改写历史、不重判或发邮件，切换记录后清除复制反馈并隔离迟到回写。

## 下载与升级

- Windows x64：[Model-IQ-Radar-v1.0.5-Windows-x64.exe](https://github.com/ahuiyuchuan/model-iq-radar/releases/download/v1.0.5/Model-IQ-Radar-v1.0.5-Windows-x64.exe)，下载后直接运行，需要 WebView2 Runtime。
- 从托盘完全退出旧版后运行新版，沿用配置、历史及系统凭据；数据库 schema v3、配置备份 v3 不变，无新增迁移或依赖升级。传输诊断格式 2、正式标记 `dual_protocol_stream`，旧 Beta 文件不改写。
- 建议升级前备份完整应用数据目录。回退到 v1.0.4 可退出后更换 EXE；已清理的历史/日志不会恢复，已发邮件无法撤回。更换程序路径后，已启用自启的用户应重新设置自启路径。

## 验证与边界

- 191 项前端、126 项 Rust 测试（87 单元、17 数据完整性、22 请求回归）通过，覆盖流式终态/原文保真、双协议 HTTP 路径、EOF/超限/取消/期限、一次请求/回退关联、诊断脱敏/留存/并发/失败隔离和卡片历史交互。
- Clippy 全目标 `-D warnings`、Prettier、rustfmt、TypeScript/Vite 和 Windows x64 生产构建通过；保留既有 chunk 体积与 MSVC 导入库提示。最终 EXE 16,693,760 字节，SHA-256 `2456a2dfd4e423acd9a49070a8a1242f5705afdbfee5b5539f28f68b4927fc0a`。完整记录见 [VALIDATION.md](https://github.com/ahuiyuchuan/model-iq-radar/blob/v1.0.5/VALIDATION.md)，逐文件复核见 [FILE_AUDIT-v1.0.5.md](https://github.com/ahuiyuchuan/model-iq-radar/blob/v1.0.5/docs/FILE_AUDIT-v1.0.5.md)。
- 用户提供的日志已分别确认两种协议的流式成功；旧非流式失败发生于等待响应头阶段的 TLS EOF，具体断链节点仍无法由客户端确定。中转缓冲或其他网络限制仍可能导致失败，本版不关闭 TLS 校验、不承诺所有服务商不再断连。
- 本轮自动验证仅使用组件、临时数据库及本机模拟 HTTP/SMTP，不操控桌面、不调用真实模型或发送真实邮件；模拟回归不替代实际服务稳定性验证。原降智规则、邮件边界及 HTML 沙箱/资源上限保持。
