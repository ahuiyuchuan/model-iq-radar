# 测智雷达 v1.1.0 使用手册

作者：ahui。通过自定义题目和连续字符串规则记录模型回答变化的 Windows x64 桌面悬浮工具。当前文档描述 v1.1.0 行为，实际检查见 [VALIDATION.md](../VALIDATION.md)，正式下载见 [GitHub Releases](https://github.com/ahuiyuchuan/model-iq-radar/releases)。

自 v1.0.3 起只交付一个 Windows x64 EXE，本地测试和正式 Release 均无需解压，也不附带说明文档包；直接运行下载的 EXE 即可。使用说明及许可证可在项目仓库查看。程序仍依赖系统 WebView2 Runtime。

## 桌宠与皮肤管理

v1.1.0新增二维桌宠与皮肤管理，采用PNG与Canvas呈现角色，搭配纵向测智卡片和海洋主题边饰。具体设计与源图见 [互动桌宠设计](DESKTOP_PET_DESIGN.md)，实际检查范围见 [VALIDATION](../VALIDATION.md)。

设置 → 皮肤管理 → 选择“蓝鲸女仆”→ 保存皮肤设置。旧配置默认经典雷达，可随时切回。支持96—192逻辑像素尺寸、动画、自主活动、临时互动文字，以及十二动作预览；预览不请求模型。保存前检查全部动作，资源不可用时提示并保留旧设置。

云朵默认显示当前结果；短按云朵打开／收起卡片，同时确认并隐藏这一次提示、结束对应的结果姿态；面板打开时保持侧坐，收起后恢复设置的默认待机姿态，测试中确认也不取消实际任务。拖动不算确认。同一结果的快照轮询、动作和面板收放不会让它重现；新任务、新记录或条件状态变化再显示。隐藏云朵撤销其命中区域，保留场景留白以稳定角色坐标；结果仍可在卡片查看，也可用角色右键菜单打开卡片，角色聚焦后Enter可切换面板。这个确认行为独立于“提示气泡”开关，不改写测试结论。

右键菜单按当前工作区剩余空间布局：动作二级菜单优先向右，右侧不足时向左，靠近底边时向上避让；一级菜单出画前等待窗口就绪，并在本次菜单会话预留两层范围，二级显隐不再缩放窗口。关闭先移除菜单画面再收回尺寸，快速取消不会被迟到回调重开。二级菜单在鼠标移到其他一级项目或离开菜单600ms后自动收起，进入二级取消计时；键盘二级导航不被鼠标离开打断。菜单退场期间若打开或增高卡片，场景同步容纳当前可见内容，避免轮廓越界回退经典。手动点播／摸头期间暂停贴边收纳，动作结束后恢复判断，测试结算不抢占主动动作。角色键盘焦点使用轮廓柔光，不再绘制透明画布的矩形蓝框。

角色在卡片左／右的位置不再绑定“当前是否贴边”：拖离边缘或移到顶部保留原侧；到达另一水平边缘后按新方向布置，拖动期间收到的方向在松手后生效，避免途中跳边。顶部云朵轮廓倒转时，正文的留尾空间也移到上方，文字／图标保持正向并居中。

顶部收纳和悬停恢复按角色屏幕横向锚点换算，不再沿用卡片左上角；右侧人物移到顶部仍保留原侧。角落因云朵或卡片超出工作区时仅作必要夹紧，恢复以当前可见探头为准，避免返回过期坐标；不改变纵向吸附、业务状态或皮肤格式。

四个选择器在桌宠场景先隐藏挂载、测量菜单，再等待窗口扩展完成才出画；高亮项仅滚动列表自身，不调用会滚动外层容器的scrollIntoView。取消或扩窗失败关闭隐藏菜单，迟到回调不得重开；菜单仍不拉长卡片。切回经典皮肤保留当前紧凑／详情状态，窗口同步恢复156／572px，不把展开内容截在紧凑窗口内。

桌宠头部旁的统一云朵默认显示真实状态：测试中、不降智、降智、测试失败。图标、文字、颜色共同区分；未测试、条件变化待重测、HTML回答和取消也准确显示，不能把旧通过继续当成当前结果。点击云朵打开或收起测智卡片；已去掉独立雷达球、全息入口和旧气泡。关闭“提示气泡”仅关闭同一云朵中的临时互动文字，未确认的结果仍保留。

结果云朵支持按住拖动，累计移动达到6逻辑像素后才开始；短按或小幅抖动仍展开／收起卡片，长按云朵不会弹出角色菜单，右键可打开菜单。松手后220ms保护鼠标合成点击，避免拖完误切面板；键盘Enter仍能操作，真实拖动期间不接受激活。贴边云朵按下先恢复完整场景再拖动；若只是短按则打开卡片。隐藏后恢复不会接续旧按下。

单击角色摸头，双击招手，按住移动拖动，长按不移动打开菜单。双击不会先触发摸头。右键一级菜单保留面板、设置、当前状态、动作和隐藏入口；右键菜单将动作统一放在“动作”二级菜单中，只列出当前皮肤实际提供的动作（内置十二项）。悬停或点击打开后，在动作入口与二级菜单之间移动保持展开；移到其他一级项目或离开整棵菜单600ms后只收起二级，短暂斜向经过不会立刻关闭。重新进入动作入口／二级菜单取消计时；键盘焦点在二级时保留，Escape或左方向键返回。方向键/Home/End导航，左方向键或Escape返回上一级，外部点击关闭；长列表限高滚动。点播只预览姿态，不修改真实测试结论、不触发模型或邮件；卡片展开时先收起卡片，再预览动作，避免破坏侧坐关系。二级菜单优先向右，右侧空间不足时向左，不随人物方位固定方向；一级菜单会话预留两层窗口范围，二级显隐仅调整命中掩码，整棵菜单关闭后释放预留范围。拖动期间不会被自主动作或结果姿态抢占；非贴边松手先短暂显示“放下站稳”，再处理仍有效的结果反馈；贴边时跳过这些驻留，直接收为探头。条件失效或新测试开始后不会补播旧庆祝，互动不触发额外模型调用或邮件。

展开时同一角色侧坐搭在360px宽的卡片左上，人物倍率不变，保留当前海洋配色、边角装饰及头部结果云朵。第一行接口分组／模型、第二行测试规则／推理强度，各有两个独立选择器，默认按70%／30%分列。展开后从上到下为测试结果、模型回答、完整测试时间、耗时及倒计时、复制与测试按钮、底部说明；长回答在内容区滚动。桌宠紧凑卡片176px高，文字、HTML预览与原始回答详情统一546px（以原文字详情596px为基准缩短50px），为角色和边饰保留必要空间；经典外观仍为360×156px紧凑、360×572px展开。下拉菜单独立显示，不拉长卡片，也不能被窗口裁掉。“收起为桌宠”入口返回角色。HTML放大与恢复沿用安全预览，不能被角色或边饰挡住。

开启自主活动后，空闲7—16秒从已提供的招手、伸懒腰、侧坐和鞠躬中选择，避免连续重复；测试、拖动、贴边和打开面板优先。关闭自主活动仍保留基础待机和主动互动。“启用角色动画”控制待机图集与动作切换过渡，本轮待机只是16帧、上下最多1源像素的整体轻移，未制作专用眨眼或全身连续动画。招手等十一种额外姿态为静态原画，统一使用96ms短溶解避免闪空，停稳后不扭动脸部或身体；短溶解不是连续肢体运动；不把它描述为骨骼动画。

导入皮肤使用自包含JSON包，选择并保存后生效。当前启用和内置皮肤不可移除，自定义包移除前需要确认。配置备份只带偏好/ID，换电脑需重新导入自定义图片包，缺失时回退经典。重置“悬浮设置”恢复经典但保留已导入包。皮肤schema1新增四个可选动作，旧包缺动作回退待机；数据库/配置备份仍为v3，无数据迁移。制作、限额和回滚见 [皮肤包说明](SKIN_PACKS.md)。

本轮以独立浏览器环境验收，不读取正式凭据。浏览器检查不代表Windows底层穿透、跨屏DPI或长期性能已经验证。

开启“边缘吸附”后，把桌宠拖到工作区左、右或顶部边缘：按角色、状态云朵和已打开卡片的可见主体并集距边缘16逻辑像素判断吸附（不含临时菜单），鼠标离开180ms后收成探头；同时接近顶部与侧边时优先顶部。三种方向使用用户批准的同一张专用原画，左侧原样显示，右侧水平镜像，顶部旋转90°后水平镜像（头朝右），不改变角色比例。未确认的结果云朵在三边贴边时都显示，并朝屏幕内侧布置；文字和图标始终保持正向、不随角色镜像或旋转；右侧水平翻转云朵轮廓、顶部上下翻转轮廓，使尾巴朝向角色。测试中、不降智、降智、测试失败及其他状态继续取自真实业务；关闭“提示气泡”只去掉临时互动文字，不隐藏结果。

探头恢复先记录屏幕坐标，继续移动至少2逻辑像素才视为主动悬停；窗口缩小把探头移到静止鼠标下，不会立即反弹。点击、右键与键盘操作不需等待移动；鼠标按下探头阻止默认焦点提前移除按钮，键盘聚焦交接到可见云朵或角色，再按Enter操作卡片。该输入规则不依赖动画开关。

悬停探头恢复原场景（保留已打开的紧凑／详情卡片），点击展开测智卡片；键盘聚焦探头后恢复桌宠，再按Enter展开卡片。恢复不触发测试或邮件，当前结论持续保留。右侧完整桌宠的卡片向角色左边展开，文字与控件不翻转；拖动期间收到的方向变化暂存到松手后处理，避免角色抓取点跳动。

普通卡片打开时鼠标离开也会贴边收纳；右键菜单、选择器浮层、手动动作、拖动或HTML放大进行中不会自动收起，键盘操作也优先于收起计时；关闭吸附恢复完整角色。点击结果云朵或“收起为桌宠”仍只是收起功能卡片。旧皮肤缺少探头资源时保持完整角色；经典雷达继续使用原左／右／顶部小边签。本轮三边探头、贴边状态云朵的浏览器交互、几何及自动回归已通过，浏览器证据及覆盖范围见验证记录；Windows偶发顶部问题仍未原生复现，真实窗口坐标保存、跨屏／DPI及底层点击穿透未由浏览器验证，不能据此声称已彻底解决。

## 快速开始

1. 运行下载的 EXE，打开右上角“设置”。在“接口配置”填写分组名称、API 地址、模型 ID 和 API Key；无鉴权的本地接口可以留空密钥。
2. 模型名称可直接输入或选择已缓存列表；“拉取模型”成功后保存列表，再次拉取更新，失败保留旧列表。选择 Chat Completions 或 Responses，思考强度默认 `low`，题目超时留空继承悬浮设置的全局值；旧接口独立超时升级后不再生效。连接测试使用当前草稿，不必先保存。
3. 保存模型配置，在“测试规则”编辑默认规则，或创建命名预设后绑定到模型。自带日本首相、糖果与鹈鹕测试。题目最多 20000 个 Unicode 字符，每题支持 1—20 个判定答案，每项最多 500 个 Unicode 字符，不能只有空白或完全重复；保存保留有效空白和换行。
4. 返回悬浮窗点击“开始测试”。文字完整原始回答命中任一答案的连续字符串显示“不降智”，未命中显示“降智”；连接、协议、空响应等异常显示“测试失败”。
5. 右上角“自动测试、设置、展开/收起”在紧凑态与展开态位置一致。自动测试默认启用、间隔三分钟，可通过悬浮窗、托盘或设置中的同一开关控制。

接口地址可填写 `https://api.example.com/v1` 或完整的 `/chat/completions`、`/responses` 路径。按选定协议替换末段，不猜测或额外添加 `/v1`。远程接口必须 HTTPS，仅 `localhost / 127.0.0.1 / ::1` 允许 HTTP；拒绝 URL 内置凭据、查询参数、片段及自动重定向。

新建接口默认选择“糖果测试”（答案 `21颗`），规则编辑页首次打开也选中糖果；已有接口保留保存的规则绑定。糖果预设已被删除时，新建接口回退现存默认规则；只有明确清空并恢复“测试规则”才重建内置题目并把保留接口改绑糖果。原默认规则“日本首相测试”（允许改名）继续保留，题目如下，题目与要求之间保留空行，判定答案为 `高市早苗`：

```text
仅依据你的记忆，你所知道的最新一位日本首相是谁？

要求：
- 全程禁止联网、搜索互联网、读取本机文件。
- 只能依据已有的模型知识回答，不得查询或核实实时信息。
```

自带“糖果测试”使用用户提供的完整糖果题目和数量表，判定答案为 `21颗`。旧配置首次升级补入一次，不覆盖同 ID 的已有修改，删除后不会在重启时复建；原题目及已改名称保留。

新增内置“鹈鹕测试”，题目原文如下：

```text
创建一个HTML，内容是SVG绘制一个黑天鹅骑自行车的2D动画，你不需要任何测试。

要求：
- 全程禁止联网、搜索互联网、读取本机文件。
- 只能依据已有的模型知识回答，不得查询或核实实时信息。
```

HTML 识别优先于关键词判断：有效 HTML 只展示动画，不评价画面质量、不发邮件。预设沿用现有答案字段保存 `<svg` 作为非 HTML 回答的备用文本匹配，不用于判断动画正确性。题目约束原样发给被测模型，不限制客户端向配置的 API 发送请求。

内置规则标记升级至 2，并在启动历史检查事务中立即保存：只补入缺失的鹈鹕固定 ID，保留同 ID 修改；升级后再删除不会重建。日本首相题目只有与旧内置正文完全相同时才更新，名称、答案、超时和自定义正文均保留，历史快照不重写。规则内容变更后按原有机制提示重测；数据库 schema 与配置备份仍为 v3。v1.0.3—v1.1.0 可在退出后更换 EXE；回退到 v1.0.2 及更早版本须恢复与目标版本匹配的完整数据目录备份。

默认规则可改名但不可删除，身份和模型绑定不随名称变化。“恢复默认”仅把默认规则草稿恢复为内置日本首相题答及继承超时，保留当前名称；其他已保存预设显示“还原已保存”，仅恢复自身题答、名称和超时；新建草稿没有还原操作。任何还原都需保存后生效，不串用默认题目。

接口配置与测试规则统一使用“选择器＋右侧新增按钮”：下拉列表只选择已有配置或规则，点击“＋ 新增”后编辑未保存草稿，再点击底部保存。切换前仍提供保存、放弃、取消保护；删除配置或已保存规则预设均在底部操作栏，规则删除会先说明模型绑定影响。

侧栏“关于”固定在最后，后续功能入口位于它之前。历史起止日期点击整个框打开应用内深色日历，不调用系统白色日历；也可用 Enter、空格、F4 或 Alt+↓ 打开，Tab 聚焦不弹出。日历支持方向键、Home/End、PageUp/PageDown 翻月（按住 Shift 翻年），Escape 关闭并恢复输入焦点；保留手动日期输入、“今天”和“清空”，支持 0001—9999 年。选择日期只改变筛选，不请求模型或保存配置。弹层靠近边界时翻转或在主体内移位，避免越过固定底栏；外部点击、离焦、滚动或缩放时关闭，Alt+F4 等宿主快捷键保持原行为。

## 分类清空与恢复初始状态

悬浮设置底部提供“恢复所有设置”和“清除所有数据”。按用户确认，两个入口执行相同操作：清空所选分类并恢复初始状态。打开时不预选，支持独立勾选、全选及取消全选；未选分类保留。选择后先列出最终范围，再点击“确认清空并恢复初始状态”立即生效，无需再次保存设置。当前未保存草稿先走保存/放弃/取消保护。

| 分类     | 清空和恢复范围                                                                                                                                                   |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 接口配置 | 全部接口分组、API Key、模型目录缓存及通知恢复判断依据；历史正文保留。                                                                                            |
| 测试规则 | 删除自定义规则，恢复内置日本首相、糖果、鹈鹕测试；所有保留接口解除原绑定、改用糖果测试。                                                                         |

## 模型、协议与测试规则

- 每个模型配置分别保存接口模式、模型 ID、思考强度及规则预设绑定。新建配置默认 Responses 并开启失败切换协议；已有配置保留已保存选择，旧配置缺字段仍为 Chat Completions/关闭。缺省思考强度为 `low`，明确选择“不指定”时不发送该参数。
- 可选择 `low / medium / high / xhigh / 不指定`。请按模型和服务商支持范围选择；列表不是接口能力探测结果。不支持时明确报错，不自动换档；协议回退可在接口模式下手动关闭。
- Chat Completions 从完整最终助手消息读取正文，拒绝显式非助手消息及拒绝回答。Responses 从已完成的 assistant 消息读取最终 `output_text`，排除明确标记为 `commentary` 的中间说明，未知阶段报协议失败；旧兼容接口省略阶段时沿用原解析。推理内容、工具调用和不明确的结束状态不用于判定。客户端只发独立题目，不带判定字符串、历史、工具或本机文件。
- 每道测试规则可覆盖正整数秒总体超时，否则继承悬浮设置的全局默认 300 秒；同一规则绑定的所有模型共用该值，旧接口独立超时不迁移、不生效。已有全局显式值继续保留，只有新配置或缺字段时默认 300 秒；旧接口超时不会转换为规则覆盖值，也不再导出。“测试连接”和正式测试采用相同有效超时。请求开始时捕获设置，后续修改不会改变已发出请求的期限。
- 300 秒仅为默认值，1 秒、600 秒、3600 秒等正整数均可使用；零、负数、小数和无法精确保存的整数会被拒绝。规则留空表示继承，全局超时必须填写。秒数仍受 JavaScript 安全整数表示约束（最多 9,007,199,254,740,991）；超出系统计时器可表示范围的期限在发请求前明确报错，不溢出、不截断、不改用默认值。
- 规则页可创建、选择和编辑命名预设，模型可绑定预设或沿用默认规则；绑定选择器只展示规则名称，不加“沿用默认：”前缀，默认绑定含义保持不变。悬浮卡片第一行按分组名称/模型/拉取按钮动态使用 65%/25%/10% 或 70%/30%，第二行规则/思考等级使用 70%/30%；四个选择器共用高度、字号和箭头尺寸，强度完整显示；模型菜单左侧显示名称、模型和规则，右侧只显示等级值并与勾选图标同一行居中。切换只保存该模型对应字段，不自动请求、不重置倒计时，测试中禁用且重复点击只提交一次；外部切换不覆盖设置页其他草稿。删除正在使用的预设前必须确认受影响模型改回默认规则，解绑与删除一起保存；失效引用不能静默改用另一题目。
- 切换测试条件后，优先恢复同一接口分组、相同完整条件的最近保留记录，包含当次回答、状态、时间和耗时；例如糖果测完再测鹈鹕，切回糖果即可查看原糖果结果。失败/取消也按最近顺序显示，不跳过它们找旧通过。当前条件没有匹配或旧记录缺少摘要时，继续展示同分组上次保留的回答、HTML、时间和耗时，支持原文复制/预览放大；显示“待重新测试”和“上次回答 · 当次协议”，不沿用旧结论，历史错误/取消中的 HTML 仍不执行。切回已测条件恢复对应记录；历史已清空且无分组记录时才显示暂无数据。条件包含规范化请求地址、模型、实际题目和全部判定答案、协议及回退开关、思考强度、有效超时，以及实际替换/移除 API Key 时更新的本机随机修订标识；不保存密钥散列。重复保存相同凭据、配置名、预设名和外观变更不影响有效性；切换查看不重测、不重判、不修改历史、不发送邮件。
- 新历史保存当次规则名称、全部答案和条件 SHA-256 摘要；旧记录缺规则名显示“未记录”，不猜测当前名称。单答案摘要保持版本 2 兼容，多答案使用版本 3，名称不参与摘要；旧历史缺少摘要时无法确认条件相同，因此当前状态提示重测。历史记录及其原始判定不被重算或改写。

## 模型列表与连接诊断

- “拉取模型”从同一服务的 `/models` 请求列表，兼容 `data[].id` 以及部分服务的 `models[].id/slug`，排序去重后加载模型名称自身的可编辑深色选择器，不另开第二个下拉。箭头可浏览全部缓存，主动输入时筛选，失焦不自动替换模型，空格/首尾光标及输入法保留；列表不保证额度或实际可调用性。
- 成功列表在本机 SQLite 持久缓存，已保存接口自动关联，未保存接口需保存后关联；重启可直接选用。新拉取原子替换，失败保留旧列表；切换接口、地址或凭据清除草稿关联，异步旧结果不能覆盖新目录。缓存不含 API Key 或其散列，使用随机句柄与规范化 `/models` 端点隔离；最多 5000 项/1 MiB 每份、100 份/16 MiB 总正文，按最近更新淘汰，缺失时仍可手填或重新拉取。模型缓存不随配置备份迁移。
- 悬浮窗只在当前分组目录为空时显示拉取按钮；有目录时隐藏，可到接口设置再次刷新。当前模型即使不在目录中仍显示原 ID，不自动选择候选。拉取和选择分别去重，菜单互斥，运行中禁用修改；迟到响应按分组、地址、凭据修订与目录句柄隔离。
- 模型列表沿用配置根路径。例如 `/v1`、`/v1/chat/completions` 或 `/v1/responses` 对应 `/v1/models`，不额外添加版本号。15 秒总体超时、1 MiB 响应上限，不重定向、不重试。
- “测试连接”使用当前草稿的接口模式、模型、思考强度和有效超时，发送独立短消息“请只回复 OK。”，可能产生 API 费用；不发测试题目、不执行判定、不写历史、不重置自动测试周期。
- 密钥草稿优先；地址未变且留空时可复用已保存凭据。修改实际目标地址后必须明确填入新密钥或移除旧密钥，不能将旧凭据隐式发送给新服务。
- 两种诊断共用门禁，禁止重复提交。修改目标配置、地址、模型或凭据后，过期诊断结果不回填表单。
- 错误详情展示可获取的错误分类、HTTP 状态码和经过约束的服务商请求编号。一键诊断复制包含版本、时间、模型与请求设置，排除密钥、鉴权头、完整题目和回答；不展示原始服务端错误正文。

### Responses SSE 兼容与本地响应诊断

两种协议均主动发送 `stream: true`，不新增设置项；正式手动/自动测试与“测试连接”共用请求方式。完整 JSON 优先沿用原解析；否则根据 `text/event-stream`（支持大小写及参数）或正文开头的 SSE 字段识别事件流，再按所选协议解析。兼容 LF/CRLF/CR、UTF-8 BOM、保活注释及多行 data，不逐字刷新界面、不增加请求或自动重发非流式。

Responses 不把推理、增量和用量元数据拼入答案；仅提取唯一 `response.completed` 中的完整 response，再由原规则检查顶层完成状态、最终助手消息、拒绝/工具调用和答案。无需 `[DONE]`，它也不能替代完整结束事件；损坏 JSON、重复结束、真实混流、失败事件或末尾未封闭的数据事件均不当作成功。v1.0.6 对已核实的空前导增加最小兼容：此前所有数据事件必须属于结构白名单，生命周期明确 in_progress/output=[]，空消息和空文本具有正确的 item_id/output_index/content_index 关联；仅允许一次新的 response.created 切换 ID。任何非空正文、推理/工具/拒绝、终态、未知事件或无法证明为空的结构都会关闭切换资格；不按 ID 前缀判断、不拼接两响应正文。

Chat Completions 只按同一 `chunk.id`、`choices[0].index=0` 顺序追加 `delta.content`，保留原文空白和换行，排除推理/用量；检查分块类型、显式角色和结束状态。角色沿用 JSON 的旧网关省略兼容，但明确非 assistant、拒绝或工具调用仍拒绝；多候选、混合响应、重复结束或完成后追加候选数据均报错。完成后允许标准 `choices=[]` 用量尾块；须同时具备 `finish_reason: stop`、完整 `[DONE]` 事件和 HTTP EOF 才可成功，缺任何结束证据、空正文、length/过滤等均不判成功。两种协议的流式结束格式不能混用；仍保留 2 MiB、整次总期限及取消边界。

仍须先读到 EOF，整段响应（包括推理和元数据）沿用 2 MiB 上限。即使已收到某个结束片段，随后读取中断、超限、取消或超时也不判成功；如果服务端一直不关闭正文，则仍按原总超时报错。解析不重连、不另发请求、不修改协议或回退开关；正常兼容后的成功不再因错误套用 JSON 解析而触发回退。Chat Completions 使用上述独立 SSE 路径，完整 JSON 的既有兼容继续保留。

v1.0.6 将空前导兼容及双协议失败原文诊断纳入正式版。Chat 缺少真实失败原文，本版保留严格 ID 一致性校验；转换代码可以解释一种可能机制，但不能据此确认服务商线上行为或放宽任意 ID 变化。

两协议正式手动/自动测试收到响应头后，凡解析、最终协议验证或读取失败，均尽力保存本次已经收到的原始字节；正常成功仅保存 transport。非成功 HTTP 沿用立即报错，不为诊断继续读正文，无字节时只保留带省略原因的元数据；未收到响应头仅有 transport。“测试连接”不采集，不额外调用接口、不改变判定和协议回退。

Windows 目录为 `%APPDATA%\com.ahui.model-probe\response-diagnostics`（当前账户为 `C:\Users\Admin\AppData\Roaming\com.ahui.model-probe\response-diagnostics`）。原始响应格式 3：`responses-<UTC年月日T时分秒.毫秒Z>-<UUID>.json` 或 `chat_completions-<同格式时间>-<UUID>.json`，正文为同名前缀 `.body.bin`。记录实际协议、起止 UTC、HTTP、Content-Type、请求编号、接收/保存字节数、完整/截断及省略标记。两协议共留存二十组，每份正文最多 2 MiB，按时间淘汰最旧组，旧格式 1/2 不改写。

`json_error` 专用于语法错误，包含原解析库的行/列，`scope` 为 `response_body` 或 `sse_event_data`；位置不是绝对字节偏移。`sse_error` 独立记录固定失败原因、从 1 起的数据事件序号、事件类型、预期/实际响应 ID；无法定位具体事件时序号为 0，Chat 的 EOF 错误沿用最后完整事件序号，无可用类型/ID 为 null。SSE 中 JSON 损坏时两者可同时存在。ID/类型脱敏限长，不回显事件 data。

`.body.bin` 按收到的字节原样保存，不转码、不格式化、不截改换行；可用文本编辑器打开，但编码不一定是 UTF-8。只有 `body_complete: true` 代表读到 EOF，并不代表 JSON 有效；中断/超时/取消为 false，超限还会标记 `body_truncated: true`，只保留前 2 MiB。`received_body_bytes` 是客户端已经交付的正文数量，超限时可能大于保存量，不能视为未读完整响应的总大小。

不记录请求体、鉴权头、URL、API Key 或其他请求凭据。若上游正文回显已知请求密钥，则不落盘该正文、不改写内容伪装脱敏，JSON 通过 `body_omission_reason` 明确说明省略；响应头同样过滤已知密钥。最多保留 20 组（正文合计最多 40 MiB），新文件写入前清理最旧组；最多四个在途写任务，队列满或文件故障只放弃本次诊断，不覆盖测试错误、不重试请求。后台写入不阻塞历史结算，程序强制退出可能使文件未写完。文件不进仓库、不嵌入 EXE、不自动上传；普通历史清空不删除这个独立目录，需要时可手动删除其中诊断文件。

人工取证时关闭协议回退，测试一次，结果出现后稍等片刻，再在资源管理器地址栏输入上述 `%APPDATA%` 路径。按修改时间找到最新 `.json`，核对 `request_id` 和时间，再获取同名前缀的 `.body.bin`；如 `body_file` 为 null，先查看省略原因。原始响应可能包含回答、推理或服务商元数据，分享前请自行检查。提供这两份原文件即可，不必重试或编辑正文。此前未留存的响应无法从空历史回答中补回，需以本次文件为依据分析。

### 本地传输诊断

v1.0.5 增加两种协议在收到响应头之前的失败取证，不修改保存的接口模式、回退开关、超时或成功判定。两种协议主动请求流式，传输诊断只采集正式手动/自动测试；“测试连接”和模型拉取不采集，发送前配置校验或凭据读取失败不属于网络尝试。

每次协议尝试（包括成功、失败、取消）异步保存一份纯 JSON，不保存题目或回答正文，成功记录用于比较等待时间。新目录为 `%APPDATA%\com.ahui.model-probe\response-diagnostics\transport`，当前账户为 `C:\Users\Admin\AppData\Roaming\com.ahui.model-probe\response-diagnostics\transport`；文件名为 `transport-<UTC年月日T时分秒.毫秒Z>-<UUID>.json`。同一次测试的两次协议尝试共用本地 `trace_id`，`attempt_index` 从 1 开始；该编号不发送给服务商，不能当作服务商请求编号。

文件记录模型、思考强度、实际协议、开始/结束 UTC 时间、当前尝试耗时、整次总超时与本次剩余预算；响应头和首个非空正文块的到达时间以当前尝试起点计毫秒。`stage` 区分发送/等待响应头、已收到响应头、读取正文、解析和完成；发送/等待阶段无法再细分出 DNS、TLS、发送是否成功。HTTP 状态、版本、Content-Type 和服务商请求编号只填实际收到的信息，未收到时为 null。正文字节数、EOF 完整标志与超限标志来自原读取过程，不为诊断多读字节。

传输日志格式 2 包含 `request_stream`（实际请求 JSON 的值）和 `build_variant`，v1.0.6 正式标记为 `sse_empty_prelude`；此前正式标记 `dual_protocol_stream` 和 Beta 标记 `sse_empty_prelude_diagnostic_beta` / `dual_protocol_stream_beta` / `responses_stream_beta` / `transport_diagnostic` 的历史文件原样保留。旧格式 1 缺这两个字段，原文件不改写。使用 `npm run tauri -- build --no-bundle` 构建，两种协议直接请求流式，不需要临时 feature，不写入配置或备份。连接测试同样请求流式但不保存传输诊断；正式对照请使用手动测试。

两种协议按前述独立契约验证，不逐字刷新界面；网关忽略流式而返回完整 JSON 时仍按既有 JSON 路径处理。官方流式契约见 [Responses 文档](https://developers.openai.com/api/docs/guides/streaming-responses)和 [Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。中转可能缓冲流或存在其他断连限制，因此不能保证流式解决故障，也不能据此认定是哪一层断开；不关闭 TLS 校验、不追加重试，回退仍遵守用户原开关。

`transport_error` 包含 reqwest 的 timeout/connect/request/body/decode 分类、最多八层脱敏错误链、可取得的 IO 错误类别及系统错误码；每层文本最多 1024 字符。应用共享总期限触发时 `timeout_source` 为 `application_total_deadline`，网络库报告超时时为 `transport`；没有底层异常（例如用户取消、应用总超时、协议拒绝）时错误链为 null。`outcome: success` 仅指请求和协议解析成功，不代表文字判定通过。

不记录接口地址、请求体、鉴权头或代理配置值；去掉 reqwest 附带 URL，错误说明中的 URL 整体隐藏，已知请求密钥及疑似鉴权片段省略。传输目录独立最多保留 20 份、每份上限 64 KiB，与原始响应诊断共用最多四个后台任务；队列满、慢盘或写入故障不改变测试结果、不额外请求、不自动重试或上传。进程退出可能来不及写完，普通历史清空不删除诊断。本版双协议原始响应 `.json`/`.body.bin` 改用格式 3，沿用 2 MiB 和共二十组限制；HTTP 拒绝无正文或正文写入失败时记录省略原因。

人工取证：从托盘完全退出旧 EXE 后启动新版，关闭自动测试及协议回退，保留要复现的分组/模型/题目/强度，手动测试一次。结果出现后稍等片刻，在资源管理器地址栏输入上述 transport 目录，按修改时间获取最新 JSON；如有回退，获取同一 `trace_id` 的全部文件。失败与成功各一份更便于比较，但不要求反复测试。若原始响应目录同时新增了任一协议正文诊断，可一并提供其同名前缀两份文件；分享前检查内容。客户端证据可说明具体错误与发生阶段，不能保证定位中转服务器内部断链节点。

切换协议后，旧 HTML 仍可查看并标记待重测，完成新测试后展示新记录。v1.0.6 新日志应为格式 2，协议为实际尝试值、`request_stream: true`、`build_variant: sse_empty_prelude`；若字段不符，先检查是否仍在运行旧进程。无论成功失败均可提供本次 JSON，不需要重复生成。退出后换回 v1.0.5 EXE 可回滚本版 SSE 兼容/历史分页逻辑，无数据库、配置备份格式迁移；旧包未实现的兼容能力不会随配置带回，已经清理的日志不会恢复。

## 原文判定与 Markdown

只有完整、非空的最终原始回答参与连续字符串匹配，命中任一答案即通过。每项独立匹配，不拼接；旧多行单答案不按换行拆分。匹配区分大小写，保留空格和换行，不做正则、语义匹配、译名转换或否定分析。“高市早苗不是答案”仍命中“高市早苗”。截断、空响应、过滤、工具调用和协议异常不归类为降智，取消也不产生成功/失败判定。

悬浮回答与历史详情共用 CommonMark + GFM，支持标题、强调、删除线、引用、列表、只读任务列表、分隔线、链接、表格、行内代码及本地语法高亮。数学公式与 Mermaid 未实现。表格和代码块内部横向滚动，长链接换行，不撑宽窗口；保留回答区高度、主体滚动与固定底栏。

Markdown 只改变显示。SQLite、JSON 导出、“复制回答”和“复制测试记录”保留原始 Markdown。例如 `**高市**早苗` 视觉上连续，但原文不包含 `高市早苗`，不命中规则。行内 HTML 示例仍作为文本显示；自动识别的 HTML/SVG 进入独立隔离预览，详情见下节；远程图片仅显示未加载说明，不请求资源。解析、高亮和净化均在本机完成；绝对 HTTP(S) 链接仅在用户主动点击后通过系统浏览器打开。

解析、高亮或净化失败时完整回退纯文本，不影响判定、历史保存和复制。超过 200000 个 JavaScript 字符单元的回答使用纯文本；单个代码块超过 20000 个字符单元不高亮。降级不截断原文。模型总体响应上限 2 MiB，连接阶段最多 15 秒。

## HTML / SVG 实际效果

- 无模式开关：HTML/HTM/SVG 代码围栏、独立完整文档/布局片段和 SVG 自动识别；普通文字和行内标签示例不执行。多个代码块保持独立，使用“片段”选择器切换，默认第一个；不拼接 CSS/JS 依赖。
- 悬浮窗展开及历史详情直接展示实际效果，右上角“放大”按钮进入页内大预览，关闭按钮或 Escape 返回。多片段才显示片段选择；无法运行时保留源码，加载失败时可重新加载。这些操作不请求模型、不生成新历史，复制仍取完整原始回答。画布以 1440×1000 为基准，首帧测量后有界扩展，再按容器宽度等比适配，长页面在预览区域滚动；超出容量时保留原始回答。
- 小预览的滚轮和键盘用于滚动页面，点击页面不会误触发放大，作品自身交互在放大后启用。预览随卡片收起、移动和滚动区域一起裁剪。放大使用当前页面弹层，暂停边缘收起；悬浮窗临时放大当前宿主，关闭后恢复原尺寸和位置，无原生预览子窗口。切换记录或关页会移除 iframe；预览不设置自动停止时长，文档也不按时间过期；原生宿主销毁时补充释放所属文档，避免重复打开设置窗口遗留占用。
- HTML 成功显示“已生成 HTML”，不判定降智，不提供人工标记，不参与新通过/降智统计，也不发送任何 HTML 邮件。HTML 不清除上次文字降智状态；下一次文字从降智恢复通过时仍可发恢复邮件。已识别部分 HTML 的请求错误不发信；回答为空或未能识别类型的请求失败沿用失败通知。
- 截断/无效 HTML 显示“HTML 预览失败”，可看源码或重新加载；不回退到关键词判定。请求错误/超时仍为“测试失败”，取消仍为“已取消”，部分源码不运行。旧历史仅新增临时预览，不重算或写回原结果、不补发邮件。
- 悬浮卡片、历史列表、历史详情共用同一 HTML 组件：宽度适配、预览区滚动、放大按钮、多片段切换、加载动画、失败重载和关闭操作一致。列表左侧信息、文字摘要和右侧箭头进入详情；HTML 的放大按钮只放大当前预览。仅可见行挂载 iframe，放大期间保留会话，关闭后的屏外行或离开列表即释放。数据库只保存原始回答、识别类型和 `html-v1` 版本，不保存图片。
- 预览留边和放大层优先沿用 HTML 自身的纯色背景，透明或未声明时使用卡片深色；不覆盖模型作品内部的背景和配色。放大直接覆盖整个当前窗口，无应用附加的面板边框、标题区或边距，关闭按钮或 Escape 返回。首次加载与放大布局期间显示加载动画，首帧完成后移除；打开选择菜单不暂停或重建 HTML，不显示“预览已停止”。
- 应用关闭浏览器默认右键菜单与保存网页、打印等浏览器快捷入口；复制回答和历史/配置导出仍走应用自身入口，导出不弹出浏览器下载浮层。
- 预览仅运行自包含 HTML/CSS/JS/SVG 与内嵌资源。iframe 只允许脚本，不开放同源、弹窗、下载、表单提交或顶层导航；响应头 CSP 阻止外网、IPC 与嵌套页面，子页面导航受本地文档白名单约束。依赖外部资源时可能显示不完整。
- 单候选最多 1 MiB、加载等待最多 12 秒、文档仓库最多十六份/16 MiB。iframe 共享浏览器渲染资源，恶意死循环可能影响界面，不承诺旧独立进程的硬资源限制。预览失败不修改已保存结果，保留源码与重载入口。

作品预览统一使用 1440×1000 桌面基准视口，页面加载并等待字体就绪后测量一次滚动尺寸，必要时扩展画布；随后测量一级可见正文与并列内容，去除外围留白，保留 16 个源页面像素的阴影余量，再按容器宽度等比适配，最高不超过原始像素比例，超高内容由宿主滚动查看。卡片、列表、详情与放大共用规则，列表预览高度为 120 像素；不改变原视口排版、SVG viewBox 或作品内部间距。桌宠 HTML、文字和原始回答详情卡片统一为 546 逻辑像素高，以原文字详情 596 像素为基准缩短 50 像素，回答展示区吸收差值，完整预览仍可放大。满屏内容、无法测量或一级节点超过 256 个时保留完整画布。画布最大 4096×8192，超出显示错误并保留原始回答；动态动画不持续重算画布，避免 `vh/vw` 引起尺寸反馈和画面跳动。放大及关闭按钮使用实色背景，悬停、键盘聚焦和按下时保持可见。

加载动画至少显示 300 毫秒：提前就绪仅补足剩余时间，超过 300 毫秒后仍等待实际首帧，不在就绪后另加 300 毫秒。首次加载、片段切换、重新加载及放大/收回共用此规则；失败及时显示错误，加载超时仍为 12 秒。新加载、切换记录或卸载会取消旧完成计时。

## 自动测试与调度

- 默认每三分钟测试当前选中的一个配置，间隔可设 1—1440 分钟；不提供多模型轮询。开关在悬浮窗、托盘、设置中同步并持久保存。
- 空闲时开启开关或修改间隔立即重新计时；手动/自动测试无论成功、失败、超时、取消或历史写入失败，都在结算后重新等待完整间隔；测试进行中不显示递减倒计时，显示“本次结束后计时”。关闭开关只停止后续自动请求，当前测试继续；重新开启重新计时。
- 保存透明度、置顶等无关设置保留剩余时间。外部快捷开关变化仅合并该字段，不能覆盖设置页其他未保存草稿。未明确编辑开关时，后端写入锁内保留其最新状态，即使跨窗口事件尚未送达也不会用旧表单撤销托盘操作。
- Rust 后端调度在紧凑、展开、边缘图标及托盘隐藏时继续，锁屏本身不暂停；退出应用后停止。手动/自动共用运行门禁，执行前复核期限，一次仅一个模型测试，不积压补跑，调度器不额外重试；模型显式启用协议回退时，由同一测试最多尝试两种协议。
- 休眠或执行暂停超过十秒后恢复完整周期，避免立即追赶任务。请求执行期间不计算下一轮间隔；在途重新开启自动测试也从该请求结算后等待完整周期。
- 断网按正常请求错误记录，当前请求结束后依既定周期继续，无网络恢复立即重试队列，不因恢复发送重复邮件。客户端不能保证服务商未处理已取消或超时请求，可能仍计费。
- 倒计时取后端实际剩余时间，前端本地更新显示；无有效配置不发送请求。关闭自动测试后隐藏倒计时。卡片两态固定显示本机 `yyyy-MM-dd HH:mm:ss` 测试时间，悬停补充相对时效；紧凑态第一行显示“测试时间”标签及完整日期，耗时/倒计时另起一行，条件变化后保留上次时间并提示待重测。

## 邮箱通知

SMTP 服务默认填写 `smtp.qq.com`，端口 465、TLS，通知总开关仍默认关闭；已有自定义 SMTP 地址保留。旧空白配置仅在表单草稿中补默认主机，保存后才持久化，不自动迁移或替换授权码。

在“邮箱通知”配置 SMTP 域名或 IP、端口、发件邮箱、发件账号、授权码及最多 10 个收件人。支持 TLS（通常 465）或 STARTTLS（通常 587），必须验证证书，不支持明文登录、跳过证书验证或填入带路径的 SMTP URL。收件邮箱用逗号、分号或换行分隔。

- 默认关闭，事件可选择“降智（每次通知）”“恢复不降智”“测试失败”。每次文字降智和未知/文字测试失败都会通知；HTML 及可识别部分 HTML 不通知；恢复仅指同一模型分组此前降智后重新不降智，手动/自动测试和规则切换均适用；手动取消不通知。
- 邮件状态按模型分组独立持久化，条件摘要只用于历史结果有效性，不再拦截通知。最多保留 1000 个模型分组，超出淘汰最早分组；重启或清理历史不会丢失状态。
- 旧版按条件保存的通知状态没有可靠的更新时间，升级时依据保留历史重建模型分组的最近有效判定，并在启动时立即保存；随后清空历史再重启也能保留恢复依据，新格式恢复不再读取整份历史。若升级前旧历史已清空，则该分组从未确认状态开始。首次不降智不发送恢复邮件，后续降智/失败仍逐次通知。配置开关、邮箱和凭据继续沿用，不补发升级前的记录。通知状态格式在 v1.0.2 增加独立版本号；v1.0.3 因规则超时将数据库 schema 和配置备份升为 v3；回退到 v1.0.2 及更早版本时，须退出程序并恢复与目标版本匹配的完整数据目录，再运行旧 EXE。v1.0.3—v1.1.0 不存在此数据格式差异。
- 邮件采用深色状态卡片，包含当次配置、模型、规则、等级、实际协议、手动/自动来源、完整时间（含 UTC 偏移）、耗时及完整模型回答；失败附错误详情、有效超时、HTTP 状态码及可获取的服务商请求编号。失败没有回答时明确提示，有部分原文时标明不参与判定。不额外附测试题目、判定答案或密钥；模型原文按文本安全显示，不渲染其中的 HTML/图片。右下角仅 GitHub 图标，点击打开项目仓库；不支持 HTML 的客户端可读取同等纯文本正文与仓库链接。图标随邮件内嵌，无需加载外部图片。授权码存 Windows 凭据管理器，不进配置数据库、历史或备份。改 SMTP 目标或发件账号后须明确输入授权码，不能复用旧服务凭据。
- “发送测试邮件”使用当前草稿，不保存表单；未启用事件通知也能试发。每次发信有独立连接和 20 秒总超时，并发邮件不会因全局忙碌门禁被丢弃；不阻塞测试、不排队重试。发送失败不会改变测智结果，邮件页面显示最近故障；同一事件不会因重启自动补发。
- 启用前需要保存有效授权码，应用必须运行并联网。关闭程序不能继续通知。本版不提供桌面弹窗提醒。

## 历史筛选、保留与导出

- 第一排分别按接口分组、模型、规则预设、思考强度组合筛选，与结果、来源、关键词和起止日期按“同时满足”生效；导出“当前筛选”复用同一结果集合。
- 候选来自历史快照，规则按当时保存的名称匹配；改名后的记录分别显示当时名称，已删除分组/规则仍可筛选。旧规则名或强度缺失时显示“未记录”，显式不发送强度显示“不指定”，不从当前配置补猜。
- 列表展示当次分组、模型、规则和“思考强度”，相关信息统一左对齐；详情短字段按窗口宽度分为三列/两列/一列，完整题目与回答始终占整行。长名称可悬停查看全文，长请求编号允许折行。复制记录/诊断的成功或失败提示仅属于当前详情，返回或切换记录时清除，异步剪贴板结果不跨页回写。

历史支持接口分组、模型、规则预设、思考强度及关键词、状态、来源、日期组合筛选。列表每页 10 条，筛选改变返回第一页；切入时加载不含题目/回答的摘要索引，仅保留集合变化才重载，每页按需取原文。搜索停止输入 250ms 后在独立只读后台线程逐条检索，旧搜索和旧页不回写；界面不复制全部回答转小写，慢检索只保留一条在途扫描。读取故障明确报错并允许刷新，不把空摘要当成真实回答。日期按本地日历日筛选，包含起止日期；删除模型配置后，已有历史分组仍可选择。详情保存当次题目、判定字符串、原始回答、来源（手动/自动）、接口模式、思考强度及有效超时。旧记录缺少字段显示“未记录”，不推测补填；已记录的“不指定”与旧缺失分别显示。

保留策略默认最近 500 条，用户可设 1—5000 条及 1—3650 天；条数留空使用 5000 条硬上限，天数留空不按时间清理。历史 JSON 正文总量另有 128 MiB 硬上限。各限制同时生效，按自增顺序保留最新记录，日期按真实 UTC 时刻比较。启动、写入结果和保存保留设置时执行真实删除，不能仅隐藏超额数据。缩短保留范围且影响现有记录时先预览并确认；配置与清理同事务提交，失败回滚。配置、凭据及邮件状态不受历史清理影响。

128 MiB 指保留 JSON 正文字节，**不是数据库文件大小承诺**；SQLite 已分配页面及 WAL 不会自动立刻缩小，不自动执行 VACUUM。“清空”二次确认后删除全部历史，不能通过界面撤销，筛选不会改变清空范围。

导出可选整个筛选结果（不限当前页）或全部仍保留的记录，以及 JSON / CSV。用户点击时才读取全量原文，期间禁用重复导出；若筛选记录已被清理则要求刷新，不生成遗漏正文的导出。包含题目、判定字符串、原始回答、模型、请求设置、时间、耗时、状态和安全诊断元数据，不包含凭据。JSON 无损保留原文；CSV 正确引用逗号、引号、换行，并对可能被表格软件执行的公式前缀加单引号转义。需要逐字复核请使用 JSON 或复制原文。

## 配置备份与迁移

设置页导出包含接口地址、接口模式、模型、思考强度、超时、规则绑定、规则预设、默认规则、偏好及非敏感邮件设置的 JSON 备份，不含历史、API Key 或邮箱授权码，存在标记归零。跨电脑不迁移窗口坐标。

导入和格式化导出均最大 4 MiB，最多 100 个模型配置、100 个自定义规则预设及额外两份固定 ID 的自带糖果和鹈鹕预设。备份格式为 v3（兼容读取 v1/v2），保存默认名称、全部答案和规则超时；未知版本拒绝。超限导出明确报错，不生成无法重新导入的文件。本机凭据修订标识不随备份迁移，替换保留本机标识，新建/复制不继承。后端先验证完整文档、引用、字段及长度，预览数量、重复项、覆盖范围和清理影响，再以一次配置事务提交；任何错误不允许部分导入。重复以稳定 ID 判断：

| 策略 | 行为                                                                     |
| ---- | ------------------------------------------------------------------------ |
| 跳过 | 同 ID 模型/预设保留本机内容，新 ID 项加入                                |
| 替换 | 同 ID 项更新；已有密钥的模型不能改变实际请求地址，否则拒绝并提示使用复制 |
| 复制 | 导入模型和预设均分配新 ID，规则引用同步重映射；复制模型没有密钥          |

三种策略均采用备份中的默认规则、偏好与非敏感邮件设置，保留本机窗口坐标；不是只导入模型列表。新建/复制配置需要补填 API Key；替换地址未变时可保留本机已有密钥。导入不读取备份宣称的凭据状态，邮件强制关闭并清除授权码存在标记，需重新填写后启用。导入不覆盖本机历史，但若备份的保留策略更短，必须确认相应清理。运行时设置应用失败不提交数据库，数据库失败恢复运行时设置。

保存或导入已提交后，若关闭边缘吸附所需的原生窗口恢复失败，会明确提示“配置已保存，但悬浮窗退出吸边失败”，切换页面仍保留警告。此时配置已生效，请按提示重启恢复窗口，无需重复保存或导入；历史清理也不会因此再次执行。

首版没有模型数量上限，因此已有超过 100 个模型的合法旧库仍可启动、编辑和删除，配置正文不会因升级被自动裁剪。新版不允许继续新增超额配置，备份/导入仍遵守上述 100 个上限；整理前可备份整个数据目录，减少到允许数量后再导出配置文件。

## 数据、兼容性与回滚

SQLite 位于 `%APPDATA%\com.ahui.model-probe\probe.db`，应用标识和凭据服务名保持 `com.ahui.model-probe`，复用已有配置、凭据及历史。API Key 按随机模型 ID 存系统凭据，SMTP 授权码单独存系统凭据。配置/历史不含密钥，保存数据库失败尝试恢复此前凭据，恢复失败会明确要求重新配置。启动会校验已保存偏好、规则绑定、模型字段和接口模式；若配置 JSON 可解析但不能执行，应用会拒绝启动且不改写配置正文、不清理历史，请先备份数据目录后使用兼容版本或手工修复配置。初始化可能创建兼容附加表及 WAL，不等于改写业务数据。

数据库使用 schema v3，读取兼容首版及 v2 数据，但 v1.0.2 及更早程序会拒绝新库，防止忽略多答案后误判或忽略规则超时。新增模型缓存、默认名称和答案快照字段；独立通知状态表不改写旧历史。`latest_test_record` 仅存模型 ID 与最近历史序号，不含回答；写入、裁剪和清空与历史同事务提交，启动从保留历史重建，接纳首次升级前的既有记录。悬浮窗优先读取当前模型及完整条件匹配的单条记录，缺少匹配时回退分组最近记录并提示重测；设置页按集合版本读取摘要索引和每页原文，主动导出才读取完整保留历史。升级前退出并备份整个数据目录；如需历史请另导出 JSON。v1.0.3—v1.1.0 的数据库和配置备份格式相同，退出后可更换对应 EXE；回退到 v1.0.2 及更早版本必须先恢复与目标版本匹配的完整数据库备份，不能直接读取 schema v3 或导入 v3 配置备份。已被清理的历史无法凭换回 EXE 恢复。不要让两个版本同时访问数据库。换电脑或 Windows 账户需重新输入凭据；复制数据目录不等于复制系统密钥。

### 失败时切换协议

接口模式下的开关按模型保存，新建默认开启，可手动关闭；已有配置保留保存值，旧配置及旧调用方缺字段仍为关闭。开启后，所选协议请求出错时在同一服务地址最多尝试另一种协议一次，不自动换档、不修改首选协议；整次测试仅生成一条历史，通知按最终结果结算一次。两次请求共用开始时捕获的有效超时；取消、总预算耗尽、配置无效或正常返回后不回退，正常答错仍判为降智。开启可能增加一次 API 调用及计费，自动测试与连接测试遵循同一开关。历史、JSON/CSV 和诊断保留当次策略、实际协议与尝试顺序；旧历史缺字段显示“未记录”。开关变更使当前结果待重测，但不重置自动测试计时。

该开关及历史快照字段是 schema v3/备份 v3 的可选扩展，不新增数据库表；缺字段时关闭，可随配置备份迁移。v1.0.2 及更旧程序会拒绝 v3 数据库/备份，回退到这些版本须退出程序并恢复与目标版本匹配的完整数据库备份；v1.0.3—v1.1.0 沿用相同格式。

设置中的二值选项统一使用蓝色开启、灰色关闭的滑动开关。点击开关或其文字、聚焦后按空格均可切换；除开机自启即时生效外，仍按各页说明保存后生效。处理期间禁用，保存失败保留草稿。回答中的任务标记仅显示原文状态，不能编辑。

皮肤也可带有面板边饰：蓝鲸皮肤的四角鲸尾、侧边水纹和底部铃铛随配色一起切换，不影响点击。旧皮肤未声明装饰时保持原样；关闭动画会同时停止边饰的轻微明暗变化。

默认待机动作可在设置 → 皮肤管理中选择并预览，保存后生效并在重启后恢复。选项包含当前皮肤实际提供的全部动作（内置十二种），包括摸头、悬空、放下与结果姿态；仅作为空闲外观，不启动拖动、不触发测试、不改写真实结论。关闭面板且没有更高优先级反馈时使用所选姿态，临时互动／自主动作结束后恢复；展开卡片仍侧坐。旧配置缺少 `preferences.skin.idleAction` 时默认为 `idle`，换肤缺少所选动作时运行时回退 `idle`，不改写已保存偏好。关闭自主活动不影响该选择，关闭动画时显示对应静态姿态；经典外观忽略此项。不更改测试条件指纹、皮肤包版本或备份版本；不认识该字段的旧程序会忽略它；回滚到仅支持五种默认姿态的早期测试版前，请先选普通待机并保存，避免其旧白名单拒绝配置。

菜单避让同时保护完整角色画布和可见结果云朵：一级／二级作为整体按工作区空间选择上下或左右位置，优先避免越界和遮挡；空间足够时二级仍优先向右。极小工作区放不下人物、云朵与两层菜单时按最少越界／重叠回退，不能保证完全无重叠。

回答期间点击云朵打开面板仍确认并隐藏当前提示；但面板自动贴边收纳后，探头旁强制恢复“测试中”云朵，因为此时卡片已不可见。悬停恢复面板后继续保持原确认状态，新结果出现时正常显示新结论；不取消、不重启任务，也不触发额外请求。此规则覆盖左／右／顶部三边和关闭临时互动提示的情况。

接口、模型、规则、推理强度共用的下拉菜单去除阴影，保留实色背景、边框、选中态和键盘焦点。
