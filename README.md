# 测智雷达 · Model IQ Radar

### 用你的问题，观察模型的每一次回答

通过自定义测试题目与连续字符串规则，记录 AI 模型回答的变化。一个基于 Tauri 2、Vue 3、TypeScript 和 Rust 的 Windows 桌面悬浮工具。

## 为什么选择测智雷达？

- **题目与规则可控**：一个题目支持 1—20 个答案，完整原始回答命中任意一项连续字符串即通过；自带日本首相、糖果与鹈鹕测试。
- **留在桌面，随时查看**：紧凑悬浮、展开详情、边缘小图标三种状态，悬停恢复，测试中显示动画。
- **持续记录变化**：默认每三分钟自动测试，每次测试结束后重新等待完整周期，历史保留当次规则和原文。
- **本地保存数据**：配置与历史存入 SQLite，API Key 单独存入 Windows 凭据管理器。

> **适用范围：适用于 GPT 6 及以上系列模型，其他模型无法保证测试准确度。** 这是产品预设说明，尚无统计准确率验证。结果只表示本次原始回答是否命中自定义字符串，不代表模型整体能力，也不能证明服务商存在或不存在降智行为。

## 快速开始

1. 运行应用，点击右上角“设置”，在“接口配置”填写分组名称、API 地址和密钥。
2. 点击“拉取模型”并选择模型 ID，或手动输入；“测试连接”会发送独立短消息，确认模型可响应，可能产生少量 API 费用。
3. 选择接口模式、思考强度（默认 `low`）并保存。在“测试规则”编辑日本首相测试、糖果测试或命名预设，可为每道题设置正整数秒超时，留空继承悬浮设置的全局值（默认 300 秒）；每个模型可以绑定不同预设；悬浮卡片可直接切换分组、模型、规则与思考等级。
4. 回到悬浮窗点击“开始测试”，使用右上角箭头查看回答。文字未命中显示“降智”，命中显示“不降智”；自动识别的 HTML/SVG 显示“已生成 HTML”，只展示效果，不判断降智、不发邮件；网络、协议、截断和空响应等异常显示“测试失败”。
5. 用悬浮窗右上角或托盘的自动测试开关控制定时请求，也可在“悬浮设置”调整周期、全局请求超时及历史保留范围；测试结束后才开始下一次完整自动测试间隔。“邮箱通知”可配置降智、恢复与失败邮件；默认关闭。“开机自启”切换立即生效，其余表单保存后生效。

接口地址示例：`https://api.example.com/v1`，也可填写完整的 `/chat/completions` 或 `/responses` 路径。应用不会猜测或自动添加 `/v1`；无鉴权的本地服务可以不填密钥，仅本机 HTTP 地址被允许。每个配置可选择 Chat Completions 或 Responses，并可设置思考强度；超时在测试规则中设置，旧接口独立超时不再生效。

新建接口默认选择“糖果测试”（答案 `21颗`）；规则编辑页首次打开也选中糖果。已有接口保留已保存的绑定；若已删除糖果预设，新建接口回退到现存默认规则。清空并恢复“测试规则”会重建内置题目，并把保留接口统一绑定到糖果。日本首相题目继续保留，内容如下，可在设置中修改：

```text
仅依据你的记忆，你所知道的最新一位日本首相是谁？

要求：
- 全程禁止联网、搜索互联网、读取本机文件。
- 只能依据已有的模型知识回答，不得查询或核实实时信息。
```

默认判定字符串为 `高市早苗`。题目里的“禁止联网”约束被测模型；客户端必须联网请求远程 API，无法核实服务商内部是否启用了隐藏检索。

内置“鹈鹕测试”要求生成黑天鹅骑自行车的 HTML/SVG 动画，有效 HTML 沿用中性展示，不判断降智、不发邮件。升级只补入一次，保留同 ID 修改；日本首相题目只精确迁移旧内置正文，自定义正文保留。

悬浮设置底部的“恢复所有设置”和“清除所有数据”均支持按五类勾选/全选，最终确认后清空所选分类并恢复初始状态；接口和邮箱类别包含对应系统凭据。历史支持分组、模型、规则、强度组合筛选，列表和多列详情显示当次快照。边界及保留策略见使用手册。

## HTML / SVG 动画回答

无需手动选择模式。明确标注 `html`/`htm`/`svg` 的代码块、完整 HTML 文档、独立布局片段和 SVG 自动进入效果预览；普通文字、单词 HTML/svg 和行内标签示例继续安全 Markdown 显示。多个代码块分别切换，默认第一段，不拼接依赖。

悬浮卡片、历史列表和历史详情共用 HTML 预览样式和交互，不附加工具栏、说明文字或外层装饰；点击画面即可页内放大，放大覆盖整个当前窗口，不另加面板边框、标题区和边距，仅保留关闭按钮。多片段回答保留必要的片段选择；无法运行的部分回答仅展示源码，加载失败时提供重新加载。初次加载与放大布局期间显示统一加载动画，首帧布局完成后再展示画面，最少显示 300 毫秒。画布以 1440×1000 为基准，首帧按页面尺寸有界扩展；测量可见正文并去除外围留白，保留阴影余量，再按实际内容等比居中，上下留边一致。满屏作品或无法可靠测量时保留完整画布，不改动作品内部布局；历史列表预览增高到 120 像素。小预览不接管鼠标，不出现预览滚动条。HTML 随卡片一起裁剪和收起，放大期间暂停边缘收起；悬浮窗只临时调整当前窗口大小，关闭后恢复原尺寸与位置，不创建原生子窗口。打开下拉菜单不暂停或重建 HTML，不显示“预览已停止”。

操作只重运行保存的回答，不再次调用模型；复制/JSON 始终保留原始回答。历史右侧展示文字摘要，或与悬浮卡片相同的沙箱 iframe 动画预览，不再生成截图。仅可见行挂载 HTML；放大期间保留会话，关闭后普通屏外行或离开列表即释放。点击 HTML 放大，点击左侧信息、文字摘要或右侧箭头进入详情。列表“模型、规则、思考强度”统一左对齐；详情复制反馈仅属于当前详情，返回列表即清除，迟到的剪贴板结果不会重新显示。详情只保存和重运行 HTML，不保存截图。预览周围留边与放大层优先沿用 HTML 自身的纯色背景；透明或未声明背景时回退到卡片深色，不改写模型原始画面。关闭按钮或 Escape 返回。宿主禁用浏览器默认右键菜单和保存/打印等快捷入口，应用自己的复制、导出仍保留，导出不再弹出浏览器下载浮层。

新 HTML 记录不参与字符串判定，不产生降智/恢复结论，不发送邮件，也不改变此前文字通知状态。识别出 HTML 的部分响应失败也不发信；尚无可识别回答的请求错误仍按原失败通知规则处理。错误/取消响应的源码不可执行；渲染失败显示“HTML 预览失败”，不会改判为降智。旧历史可以预览，原判定与导出状态不改写，不补发邮件。

预览采用 `sandbox="allow-scripts"` iframe，不开放同源、弹窗、下载、表单提交或顶层导航；独立本地协议以响应头 CSP 阻止网络、IPC、外部脚本和嵌套页面，既有主 WebView 的导航回调阻止子页面跳往其他地址。主页面 CSP 不开放内联脚本。依赖 CDN、在线图片或分离 JS/CSS 的回答会缺失资源，可查看源码。

单个候选最多 1 MiB、加载等待 12 秒、预览不设置自动停止时长；文档仓库最多十六份/16 MiB。iframe 共享浏览器渲染资源，不再提供独立进程的 CPU/内存硬限制，恶意同步死循环仍可能影响界面。预览失败不改变测试结果。数据库保持 v3 schema 和配置备份格式，不保存截图。

三处加载动画至少显示 300 毫秒，提前就绪补足剩余时间，慢加载等实际首帧，放大/收回也一致；失败及时显示错误，12 秒超时规则不变。切换记录、重新加载或卸载取消旧完成计时，避免旧页面提前结束新一轮等待。

### 回答与安全边界

- Markdown **只改变显示**。保存、复制和判定始终使用完整原文。例如 `**高市**早苗` 看起来连续，但原文不包含 `高市早苗`，不会命中该规则。
- 禁用原始 HTML 和危险链接协议，远程图片只显示说明，不自动加载；解析和高亮均在本机完成，失败回退纯文本。
- 测智与连接测试使用同一模型的有效请求超时（规则覆盖值或全局默认 300 秒；超时填写正整数秒，旧接口独立超时不再生效）；拉取模型独立使用 15 秒总体超时。
- 思考强度可选 `low / medium / high / xhigh / 不指定`，按服务商支持范围选择；不自动探测档位或换档。新建配置默认 Responses 并开启“失败时切换另一种协议”，允许手动关闭；开启时最多尝试另一协议一次，可能增加一次 API 调用。已有配置保留已保存选择，旧配置缺字段仍为 Chat Completions/回退关闭，缺省思考强度为 `low`。
- 切换地址、模型、题目、判定字符串、协议、思考强度或有效超时后，优先显示同一接口分组、相同完整请求条件的最近保留结果，连同当次回答、状态、时间和耗时一起恢复；没有匹配历史才显示待重测。失败与取消也按最近记录展示，不跳过它们寻找旧通过；旧历史缺少条件摘要不能确认匹配。实际替换 API Key 会生成新的随机修订标识，不能恢复旧凭据下的结果；不保存密钥摘要。重复保存相同密钥、改名和外观设置不影响有效性，历史原文与结论不改写，切换查看不自动请求或发邮件。
- 只发送独立用户消息，不携带历史、判定字符串、工具或本机文件内容；测试连接只发送“请只回复 OK。”。
- Responses 保持发送 `stream: false`，兼容网关实际返回的完整 JSON 或 SSE；事件流仅使用完整 `response.completed` 的最终助手正文，不拼接增量、不额外请求。仍要求 EOF、2 MiB 以内且未超时/取消。异常响应尽力写入应用本地 `response-diagnostics` 目录，最多 20 组；原始文件不自动上传，写入失败不影响测试结算，取证方法见使用手册。
- 密钥不写入配置数据库、测试历史或应用日志。浏览器开发预览不调用模型 API、不读写系统自启，也不持久化密钥。

更多约束、超长回答降级、数据备份和回滚方式见 [使用手册](docs/USER_GUIDE.md)。

## 常见问题

<details>
<summary><strong>“不降智”是否代表模型整体能力正常？</strong></summary>

不代表。它只表示本次完整原始回答包含设定字符串；“降智”只表示未命中。单题关键词结果不是综合能力评测，接口异常、截断或空响应也不会被归为降智。

</details>

<details>
<summary><strong>拉取模型失败怎么办？连接测试会写历史吗？</strong></summary>

模型名称共用一个可输入、可选择控件。成功拉取的列表保存在本机，重启后可直接选择；再次拉取原子更新，失败保留旧列表。更换地址或凭据后需重新拉取；缓存仅作建议，不保证模型可调用。部分服务不提供 `/models`，仍可手动填写准确的模型 ID。连接测试使用当前草稿的接口模式、模型和思考强度，可能计费，不执行测智判定、不写历史、不重置自动周期。超时采用规则覆盖值，否则继承已保存的全局值；旧接口超时不再生效。

</details>

<details>
<summary><strong>数据存在哪里？换电脑如何迁移？</strong></summary>

配置与历史位于 `%APPDATA%\com.ahui.model-probe\probe.db`，API Key 和邮箱授权码位于 Windows 凭据管理器。启动会验证保存配置的规则、模型和接口模式；若提示本地配置无效，请先备份整个数据目录后再修复，应用不会自动覆盖配置或删除历史。设置中可导出配置备份，导入时预览并选择跳过、替换或复制重复 ID，完整验证后一次事务提交。备份不含凭据；新配置须补填密钥，邮件导入后关闭。历史需单独导出，JSON 保留原文；CSV 为防表格公式执行会对危险前缀增加转义。备份格式升级为 v3（可读 v1—v3），数据库升级为 schema v3，防止旧程序忽略多答案或规则超时；旧接口超时不迁移。降级须退出应用并恢复升级前的完整数据库备份，不能直接用旧 EXE 读新版数据库。

v1.0.0 已有超过 100 个模型的合法旧配置仍可启动、编辑和删除；新版不继续新增超额配置。备份和导入最多 100 个模型、100 个自定义预设及额外两份自带糖果和鹈鹕预设，超限时明确报错；可先备份整个数据目录，再整理配置数量。

</details>

<details>
<summary><strong>历史保留和邮箱提醒如何工作？</strong></summary>

默认保留最近 500 条，可设置最多 5000 条及 1—3650 天，历史 JSON 正文另有 128 MiB 硬上限；各限制同时生效，删除最旧记录，缩短范围前预览并确认。物理数据库文件不保证立即缩小。

邮件仅支持 TLS/STARTTLS，最多 10 个收件人，可选降智、恢复与失败事件。正文采用深色状态卡片，包含当次模型、规则、等级、实际协议、来源、完整时间、耗时及完整模型回答；失败附错误详情。HTML 原文安全转义，图标随邮件内嵌，右下角 GitHub 图标可打开项目仓库；纯文本客户端保留同等信息和仓库链接。每次文字降智和未知/文字测试失败都会通知，HTML 及可识别部分 HTML 不通知；恢复邮件在同一模型分组此前降智后再次不降智时发送，不受手动/自动来源或规则切换影响。取消不通知，发送失败不影响结果、不排队重试，详情在邮件设置中显示。应用需要保持运行并联网，不提供桌面弹窗通知。

</details>

<details>
<summary><strong>开机自启为什么要求固定 EXE 位置？</strong></summary>

自启项指向当前 EXE 的完整路径。移动、重命名后请在新位置重新开启；删除程序或回滚到旧版前先关闭自启。仅影响当前 Windows 用户登录，不需要管理员权限。

</details>

<details>
<summary><strong>关闭窗口后为什么还在运行？</strong></summary>

关闭悬浮窗会隐藏到托盘，定时测试继续。通过托盘菜单恢复悬浮窗或完全退出程序。

</details>

<details>
<summary><strong>检查更新是否自动下载、覆盖程序？</strong></summary>

不会。应用启动后检查一次，之后每次检查结束等待完整一小时；后台成功、失败均静默，不弹窗、不密集重试、不补跑错过的轮次。“关于”保留“检查更新”按钮，主动检查提供忙碌、结果和失败重试反馈；同时到来的手动与后台请求会合并，失败保留最近成功的更新标记。页面不显示后台周期说明，新版本在关于入口提示，用户主动点击下载按钮后通过系统浏览器获取新包。版本号相同的不同构建不会互相提示更新。

</details>
